## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| copy_table → motor destino | Las filas del origen se serializan y se envían por lote al destino: los límites de parameters/rows son la frontera de integridad (un lote sobredimensionado rompe el INSERT). |
| build_multi_insert → SQL | Identificadores (table/schema/columnas) interpolados en el SQL construido: frontera de inyección. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-21 | Tampering | builders.py::build_multi_insert | mitigate | `check_identifier` fail-closed en table/schema/cada columna (mismo régimen que `build_insert`); los values van SIEMPRE como params `{n}`, nunca interpolados |
| T-07-22 | Denial of Service | transfer.py::copy_table | mitigate | Fórmula `min(MAX_PARAMS // n, MAX_ROWS)` contra los límites reales; lote mínimo 1; test spy verifica los límites |
| T-07-23 | Integrity | lote vs filas | mitigate | Equivalencia byte a byte sqlite (2_500 filas) + cross-engine canónico via `_normalize_value`; lista de columnas estable por lote |
| T-07-24 | Integrity | Oracle INSERT ALL | mitigate | Rama `multi_values=False` dedicada + test engine-heavy como sonda; fall mode recalibrar `LIMITS["oracle"]` con provenance actualizada |
| T-07-SC | Tampering | instalaciones | mitigate | Cero dependencias nuevas en este plan; `uv.lock --check` verde (sin tocar pyproject) |

<objective>
Sustituir los globales mutables `SECRET`/`GET_DB` (`security/guard.py:14-15`) por un value object `SecurityConfig` frozen en un módulo nuevo y por factorías de guards que cierran sobre la configuración inyectada, manteniendo la firma legacy y el contrato HTTP (401/403) intactos.

Hoy `_resolve` (`guard.py:24-31`) lee los globales como fallback; mutarlos cambia el comportamiento en caliente y hace imposible multi-tenant/rotación. CFG-02 introduce `SecurityConfig(secret, get_db, algorithms)` y `security_dependencies(config)`; los globales sobreviven como atributos normales (no se rompe `guard.SECRET = ...`) pero dejan de decidir cuando el guard se construyó desde config.

Purpose: CFG-02 es la mitad de seguridad del goal ("no mutable module-level global decides ... which secret is in play") y habilita multi-tenant y rotación de clave.

Output: `encino_orm/security/config.py` (frozen, sin imports opcionales a nivel de módulo), `security_dependencies(config)`, firmas legacy preservadas con fallback deprecado, export en el barrel de `security/`, y `TestSecurityConfig` en `tests/test_security.py`.

**Hallazgo que acota el riesgo (06-RESEARCH.md).** `install_error_handlers` (`http/errors.py:7-22`) NO consume configuración de seguridad: mapea `ValidationError`→422, `FailOnUpdate`→400, `QueryError`→400. Los 401/403 se lanzan como `HTTPException` DENTRO de `guard.py` (:50, :70). El contrato a preservar es el mapeo interno del guard, no `http/errors.py`.

**Preparación de la retirada de gates (06-05).** Este plan migra `db=Depends(...)`/`user=Depends(...)` a `Annotated[...]` en `guard.py` y en `tests/test_security.py` (verificado: `B008` no dispara con `Annotated`), y renombra la constante `SECRET` del test a un nombre que no dispare `S105`. 06-05 es el único dueño de `pyproject.toml` y retira los `per-file-ignores` cuando el código lo permita.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app anfitriona -> guard | el secreto y la dependency de conexión cruzan aquí; un global mutable decide para todas las apps |
| mensaje de deprecación -> logs/CI | incluir el valor del secreto lo filtra |
| `config.algorithms` -> `verify_token` | una lista no validada podría habilitar `none` o confusión de algoritmo |
| guard -> frontera HTTP | 401/403 se lanzan dentro del guard; un cambio mueve el contrato observable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-02-01 | Spoofing / Elevation of Privilege | Un secreto global compartido permite a un tenant validar tokens de otro | mitigate | `SecurityConfig` inyectado por aplicación; los guards cierran sobre `config`; mutar `guard.SECRET` no cambia la respuesta. Test `test_mutar_globales_no_cambia_el_comportamiento` |
| T-06-02-02 | Information Disclosure | El mensaje del `DeprecationWarning` incluye el valor del secreto | mitigate | El mensaje nombra el NOMBRE del global y su reemplazo, nunca el valor (Pitfall 12); test que asserta que el secreto no aparece en el mensaje |
| T-06-02-03 | Elevation of Privilege | `algorithms` mal configurado habilita `none`/confusión de algoritmo | mitigate | `SecurityConfig.algorithms` se pasa a `verify_token`, que valida contra `_ALLOWED_ALGORITHMS`; default `("HS256",)` |
| T-06-02-04 | Denial of Service | Warning por request en `_dep` degrada el rendimiento o se silencia con `-W ignore` | mitigate | El warning vive SOLO en el fallback legacy (construcción del guard), nunca por request; `resolve`/`_dep` no avisan |
| T-06-02-05 | Spoofing / Elevation | El guard deja de fallar cerrado si faltan secreto o `get_db` | mitigate | Se preserva `AuthenticationError` si no hay secreto y la validación de `get_db`; test `test_fallback_sin_globales_falla_cerrado` |
| T-06-02-06 | Tampering | `frozen=True` es evitable con `object.__setattr__` | accept | El propio código no lo hace; la garantía es frente a mutación accidental del llamador; documentar en el docstring de `SecurityConfig` |
| T-06-02-SC | Tampering | instalaciones/actualizaciones de paquetes | n/a | Este plan no instala ni actualiza dependencias (el bump de `PyJWT` es de 06-05) |
</threat_model>

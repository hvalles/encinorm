<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer workstation → CI | A commit that passes locally must be the same commit CI gates; an unpinned formatter breaks this equivalence |
| workflow YAML → merge protection | The gate is only real if the job is blocking and cannot be softened |
| ruff config → source tree | `per-file-ignores` is a suppression surface; an over-broad entry silently disables a rule family |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03 | Repudiation / Elevation | `.github/workflows/ci.yml` `lint` job | mitigate | The `lint` job is blocking, has an explicit `timeout-minutes`, and `continue-on-error` is forbidden — verified by an acceptance criterion that greps the workflow file for the string. The gate is proven by an induced failure (unused import → non-zero exit), not by a green run. |
| T-01-04 | Tampering / Supply Chain | `astral-sh/setup-uv@v5`, `ruff==0.16.8` | mitigate | Pin the uv `version:` input on `setup-uv` so CI cannot resolve a future uv with different behavior, and pin ruff exactly so `ruff format --check` output is reproducible. Full action-SHA pinning is explicitly deferred (RESEARCH §Known Threat Patterns); record that deferral as a workflow comment rather than silently omitting it. |
| T-01-05 | Repudiation | `# noqa` directives in `encino_orm/` and `tests/` | mitigate | `RUF` is in the selected set, so `RUF100` fails any unused `noqa`. Baseline is zero `# noqa` today; the acceptance criteria require `ruff check` to exit 0 without blanket suppression. |
| T-01-06 | Tampering | `[tool.ruff.lint.per-file-ignores]` | accept | Over-broad `per-file-ignores` could hide a real finding. Accepted because every entry is scoped to named files/modules, carries a Spanish comment naming the follow-up phase (Phase 2 DIAL-02, Phase 4 PT011/B017, Phase 6 CFG-03), and `S`/`PT` remain active everywhere else. |

**No package installs occur in this plan** (ruff is already a dev dependency; uv is already the project's tool), so no package-legitimacy checkpoint is required here. The supply-chain checkpoint for the newly added dev dependencies lives in plan 01-02.
</threat_model>

configuración de GitHub/PyPI + validación en TestPyPI.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → PyPI/TestPyPI | El artefacto cruza a un registro público; la identidad se prueba con OIDC |
| secreto del repo → runner | Un token de larga vida es reutilizable fuera del workflow |
| tag `v*` → job `publish` | Un tag es disparable por cualquiera con permiso de push |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-02-01 | Spoofing / Elevation | Publicación no autorizada | mitigate | Eliminar `PYPI_API_TOKEN`; OIDC con `id-token: write` solo en el job de publish; entorno `pypi` con branch `main` y aprobación |
| T-08-02-02 | Tampering | Artefacto no construido del commit tagueado | mitigate | `uses: ./.github/workflows/ci.yml` + `uv build` en el job del mismo commit; OIDC liga la identidad al workflow+environment |
| T-08-02-03 | Information disclosure | Credenciales en logs | mitigate | Sin variables `UV_PUBLISH_TOKEN`; OIDC emite tokens efímeros; no se hace `echo` de secretos |
| T-08-02-04 | Elevation of privilege | Permisos de workflow sobredimensionados | mitigate | `permissions: contents: read` + `id-token: write` únicamente; sin `write-all` |
| T-08-02-05 | Repudiation | Publicación sin trazabilidad | mitigate | Entorno con aprobación + required checks deja auditoría del run y del revisor |
| T-08-02-SC | Tampering | Instalaciones de paquetes | mitigate | No se añaden dependencias; `uv` pinado a `0.12.15` |
</threat_model>

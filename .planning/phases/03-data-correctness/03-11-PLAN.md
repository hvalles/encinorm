<objective>
Cerrar **CR-R3-01**: `Model.update`/`delete` solo PRE-comprueban el `scope()` con `load()`, pero el DML
emitido es `UPDATE/DELETE ... WHERE <claves>` sin predicado de alcance. Con una clave de escritura no-PK
y no única, la escritura cruza tenants (reproducido sobre SQLite: `update(keys=["grupo"])` bajo
`scope(tenant=1)` modificó 2 filas de 2 tenants). Este es el residual raíz que la ronda 3 no cerró y que
su documentación sobreafirmó.

Purpose: `scope()` está documentado como filtro de VISIBILIDAD (tenant/usuario); que las lecturas lo
respeten y las escrituras no es un agujero de seguridad (modificación/borrado entre tenants). Además,
`CachedModel._resolve_pk_values` (ronda 3) asume que la escritura afecta a las filas que `search`
devuelve; con el DML acotado por scope, la sonda y la escritura ven el mismo conjunto (cierra también
WR-R3-01).

Output: `encino_orm/model/model.py` con un helper `_scoped_dml` y su uso en `do_update`/`do_delete`;
`tests/test_scope_softdelete.py` con la regresión multi-tenant (RED antes, GREEN después).
</objective>

    ```python
    def _scoped_dml(qry: Query, scope_filter, column_map) -> Query:
        """Añade el `scope()` activo al WHERE de un DML ligado (CR-R3-01)."""
        frag, sparams = scope_filter.map_fields(column_map).to_sql()
        frag = _shift_placeholders(frag, len(qry.fields))
        template = f"{qry.sql_template} AND ({frag})"
        return Query(template, list(qry.fields) + list(sparams), ignore_duplicated=qry.ignore_duplicated)
    ```

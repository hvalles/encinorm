# Technology Stack

**Analysis Date:** 2026-09-17

## Languages

**Primary:**
- Python `>=3.10` (`requires-python` in `pyproject.toml`) - Entire library under `encino_orm/` and test suite under `tests/`. CI matrix exercises 3.10, 3.11, 3.12 and 3.13 (`.github/workflows/ci.yml`); local virtualenv is CPython 3.10.18 (`.venv/pyvenv.cfg`).

**Secondary:**
- Markdown - User docs in `docs/` and design docs in `docs/design/`, rendered by MkDocs (`mkdocs.yml`).
- YAML - CI/CD workflows (`.github/workflows/*.yml`), container topology (`docker-compose.yml`), docs config (`mkdocs.yml`).
- SQL - Dialect-specific DDL/DML generated by each engine module and `encino_orm/sql.py`.

## Runtime

**Environment:**
- CPython with `asyncio` event loop; the entire data-access API is async (`async def connect/execute/fetch_*`). On Windows the test suite forces `asyncio.WindowsSelectorEventLoopPolicy()` (`tests/conftest.py`).

**Package Manager:**
- `uv` (lockfile `uv.lock`, local uv 0.8.22 per `.venv/pyvenv.cfg`). CI installs via `astral-sh/setup-uv@v5`.
- Lockfile: present (`uv.lock`, lock format version 1).
- Build backend: `hatchling` (`pyproject.toml` `[build-system]`), wheel packages `encino_orm`.
- Distribution: PyPI project `encino-orm`, version `0.2.6`.

## Configuration

**Environment:**
- No `.env` file present (`.gitignore` ignores `.env`). Configuration is passed programmatically to `Db.connect(**kwargs)` or read from environment variables in the test suite (`tests/test_*.py`) using the `ENCINO_ORM_*` namespace (documented in `docs/docker.md`).
- Engine connection kwargs: SQLite `database` (`:memory:` default); MySQL/MariaDB `host/port/user/password/db`; PostgreSQL `host/port/user/password/database`; SQL Server `host/port/user/password/db/driver/encrypt/trust_server_certificate`; Oracle `host/port/service_name/user/password`.
- Security configuration is set at app startup via module globals `encino_orm.security.guard.SECRET` and `encino_orm.security.guard.GET_DB` (`encino_orm/security/guard.py`).
- Redis cache URL defaults to `redis://localhost` in `RedisCacheBackend.__init__` (`encino_orm/model/cache_backend.py`).

**Build:**
- `pyproject.toml` - metadata, dependencies, extras, CLI entry point (`encino_orm = "encino_orm.cli:main"`), pytest config.
- `uv.lock` - resolved dependency lock.
- `mkdocs.yml` - docs site name/theme/nav; builds to `site/` (generated, gitignored).
- `docker-compose.yml` - local service topology for integration tests (MySQL 8.0, MariaDB 11, PostgreSQL 16-alpine, MSSQL 2022-latest, Oracle XE 21-slim, Redis latest).

**CI/CD config:**
- `.github/workflows/ci.yml` - test matrix Python 3.10–3.13 on `ubuntu-latest` with MySQL 8.0 and PostgreSQL 16 service containers; runs `uv sync --extra http --extra security --extra graphql` then `uv run pytest -q`.
- `.github/workflows/docs.yml` - builds `mkdocs build --strict` and deploys to GitHub Pages.
- `.github/workflows/release.yml` - on `v*` tags, `uv build` + `uv publish` to PyPI via `PYPI_API_TOKEN` (Trusted Publishing/OIDC alternative documented inline).
- `.github/workflows/publish-testpypi.yml` - manual `workflow_dispatch` publish to TestPyPI via `TEST_PYPI_API_TOKEN`.

## Platform Requirements

**Development:**
- Python 3.10+ and `uv`.
- For full integration test suite: Docker (or local equivalents) for MySQL 8.0, MariaDB 11, PostgreSQL 16, SQL Server 2022, Oracle XE 21, Redis. Integration tests skip automatically when a server is unavailable.
- SQL Server extra requires **ODBC Driver 18 for SQL Server** installed on the host (`README.md`, `docs/docker.md`).
- Windows dev host (working directory `C:\Users\Hector\projects\db`); CI runs on Linux (`ubuntu-latest`).

**Production:**
- Distributed as a pure-Python wheel `encino-orm` on PyPI (`dist/encino_orm-0.2.5-*` artifacts present locally).
- No server component of its own; the library is embedded in a host async application. Optional product layers (FastAPI app, GraphQL schema) run in the host app.
- Documentation published at `https://hvalles.github.io/encinorm/`.
